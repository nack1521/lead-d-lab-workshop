## Required changes
1. Create room: global list has ONE enabled `สร้างห้องใหม่` button, no pre-entry title field. Click -> dialog/page with room title, cancel and confirm create. Only confirm sends creation request. Prevent duplicate submits. Cancel creates no row. After successful create, enter the new room's Questions workspace; backend still validates title.
2. Spacing: measure actual rendered desktop and phone, not source only. Consistent 4px rhythm: proposed desktop main padding 32px, column gaps 24px, editor inner 24px, label-to-field 8px, field groups 24px; mobile main/inner 16px. Controls minimum 44px; single-line Create label; room list rows must be compact rectangular/list rows, not huge pills, with aligned title/metadata/status and comfortable 16–24px inner padding. No overflowing/clipped sidebar title. Keep layout fluid, test actual screenshots around 1440/1280 and 390px; these are proposed implementation measurements, not measured values from user screenshot.
3. Question types: one deliberate group of THREE equal-width controls, `คะแนน`, `ตัวเลือก`, `ข้อความ`. Use one full horizontal row when there is adequate space OR stack all three vertically at narrower widths. Never 2+1 wrapping. Separate the group from numbered question list and editor sections. Preserve accessible selection/focus and clear active state.
4. Dashboard is REPORTING: show score/choice graphs for EACH question directly (with compact navigator if useful), regardless of receiving state. Do not require clicking `เปิด` to reveal a result, and do not display a question-name/n-only list as the report. Distinguish report selection (`ดูผล`) from actual lifecycle control (`เปิดรับคำตอบ`). Charts use persisted report data for draft/open/closed/ended as applicable, including HR read-only ended-room reports. Score mean/distribution and ranked horizontal choice bars retain n/base. Empty questions have a labelled zero-state plot, never fabricated answers/mean.
5. Text: show exactly latest THREE responses per text question (new explicit user decision), not five. If more than three exist, button `ดูคำตอบเพิ่มเติม` opens a distinct paginated detail view/dialog/section; stable timestamp/id order, real cursor/has_more. Do not duplicate first three both in summary and expansion. Text itself remains a text feed, NOT a numeric graph. Apply same reporting contract to HR.
6. End-state report: reproduce user's `เปิด` -> room ended error. Verify room ID, authoritative phase and exact button action. Fresh draft/open rooms must publish/open without ROOM_ENDED, and must never be accidentally ended by viewing results. Ended-room reports remain accessible with no Open controls. Hide/disable invalid mutations and explain neutral ended status; do NOT silently reopen/reset/delete history. Add explicit confirmation for irreversible End action so adjacent controls cannot terminate a room accidentally. Preserve existing endpoint mutation guard.
