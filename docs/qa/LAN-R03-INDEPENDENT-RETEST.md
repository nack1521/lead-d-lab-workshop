## Remaining findings

### R03-QA-01 — High, static backpressure contract gap (LAN-FU-01)
On upstream OPEN, the pre-open queue is spliced and sent directly with no `bufferedAmount` budget check (`lan/lan-entry.ts:186–197`), unlike subsequent OPEN messages (`:234–245`). Queue has a finite independent cap, so do not call it an unbounded pre-open queue; however the configured downstream OPEN budget can be exceeded by the flush, especially when limits differ. Also inspect supported Bun `ws.send` backpressure/drop return (`:206–215`): the current code ignores it. Require bounded queue-flush handling, explicit send-return handling and low-resource tests with smaller OPEN budget than queued bytes plus slow downstream. This is a code-path finding; no real data loss or DoS reproduced.

### R03-QA-02 — Medium, production issuer override is not isolated (LAN-FU-02)
`LAN_ALLOW_TEST_ADDRESS=1` in `lan/generate-certs.sh:18–22` disables explicit address validation even when the generator targets its default active certificate directory. There is no check that the opt-in is restricted to an isolated test directory. A locally configured override can therefore generate a leaf for an address outside the intended selection rules; this does not prove that the LAN listener would bind it or that public exposure occurred. Separate the fixture generator or enforce an unambiguous non-active isolated test destination; test both bypass refusal and safe test-only use without touching active keys. Also add the requested bounded listener SAN-mismatch startup refusal test rather than relying on the helper-only assertion.

### R03-QA-03 — Medium, verifier refusal and cleanup not fully fail-safe (LAN-FU-03)
`lan/verify.ts:18–25` issues a new facilitator grant before snapshotting and refusing unsupported lifecycle states (`:100–124`), so the stated 'no mutation performed' on refusal is not literally true for the fixture database. A supported prior state is restored by opening its prior question in `finally` even when failure occurred before any lifecycle mutation (`:315–346`); that can increment revision/emit events and is not an exact no-op. Open attempts are appended to `sockets` at `:59–60` but only `openedSockets` are closed/awaited (`:301–312`), so a connection that times out before `open` is not explicitly cleaned up by that loop. These are source-based scenarios, not independent live reproductions. Move side-effecting grant creation after supported-state preflight where possible, track whether lifecycle mutation actually happened, and ensure connecting as well as opened sockets are closed/settled. Test unsupported/no-active/closed refusal, poll-first and failure after mutation against isolated synthetic fixtures, and exact frame/control revision plus DB correlation. Preserve real, independently scoped producer success rather than relabeling it failure.
